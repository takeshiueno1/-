# 交通費精算機能 設計書

## 1. 目的

既存の勤怠管理システムへ、交通費の月次入力、申請、段階承認、差戻し、総務精算、電子印、監査証跡を追加する。

交通費機能は勤務表機能から分離し、既存の勤務表入力、計算、Excel取込・出力、削除、共有機能へ影響させない。認証、社員マスター、監査ログ、CSRF、セッション、Docker Compose実行環境のみを共通基盤として利用する。

## 2. 参照帳票

参照元は「交通費(上野)_202607.xlsm」の「交通費」シートである。帳票から次の要素を継承する。

- 所属、氏名、申請日、申請者印
- 対象年月
- 利用日、発地、着地
- 鉄道、バス、その他の料金
- 片道・往復
- 交通費発生理由
- 経由、路線、その他詳細
- 交通手段別合計、月合計
- 上長または担当リーダー、部長クラス、総務の確認欄

参照ファイルにはVBAプロジェクト、ActiveX、外部リンク、外部データ接続、図形へのマクロ割り当ては存在しない。Web機能として再現する対象は帳票レイアウト、入力規則、計算、承認業務であり、マクロ互換機能は対象外とする。

## 3. スコープ

### 3.1 対象

- 本人による月次交通費申請の作成、下書き保存、編集、参照
- 月100件までの明細入力
- 片道・往復に基づく金額自動計算
- 申請者による電子印付き申請
- 上長または担当リーダーによる第1承認・差戻し
- 部長クラスによる第2承認・差戻し
- 総務精算担当による精算済み処理
- 承認履歴、差戻し理由、内容ハッシュ、監査ログ
- A4縦1ページを基準とする印刷表示
- 対象年月と状態の一覧・検索
- ローカル動作確認専用アカウント

### 3.2 対象外

- 鉄道運賃検索、経路検索、ICカード連携
- 会計システム、銀行振込、給与システムとの自動連携
- 領収書画像の添付
- 印影画像ファイルの登録・保存
- 勤務表と交通費申請の作成必須関係
- 交通費Excelファイルの取込

## 4. 画面構成

### 4.1 ホーム

一般・役職者のホームへ次の選択肢を表示する。

1. 新規で勤務表を作成
2. 過去分を参照・編集
3. 交通費を入力

既存の勤務表2機能は表示、遷移、処理を変更しない。交通費は独立した画面へ遷移する。

### 4.2 交通費ホーム

- 新しい交通費申請を作成
- 下書き・差戻し申請を編集
- 申請済み・承認済み・精算済み申請を参照
- 自分が第1または第2承認者に指定された承認待ち申請を確認
- `ROLE_EXPENSE_ACCOUNTING` 保有者が総務精算待ち申請を確認

### 4.3 交通費入力

対象年月を必須表示し、申請者の所属、氏名はログイン中の社員マスターから自動設定する。申請者は所属、氏名を変更できない。

明細は追加・削除可能とし、1申請100件までとする。同じ日、経路、金額、片道・往復が一致する明細も登録可能だが、画面に重複候補警告を表示する。

## 5. 入力項目

月次申請は社員1人、対象年月ごとに1件とする。

明細は次の項目を持つ。

| 項目 | 型・上限 | 必須 | 備考 |
|---|---|---|---|
| 利用日 | 日付 | 必須 | 対象年月内の実在日 |
| 発地 | 文字列100文字 | 必須 | 前後空白を除去 |
| 着地 | 文字列100文字 | 必須 | 前後空白を除去 |
| 鉄道片道料金 | 0以上の整数 | 条件付き | 3料金のいずれか1つは1円以上 |
| バス片道料金 | 0以上の整数 | 条件付き | 3料金のいずれか1つは1円以上 |
| その他片道料金 | 0以上の整数 | 条件付き | 1円以上なら詳細必須 |
| 利用区分 | `ONE_WAY` / `ROUND_TRIP` | 必須 | 片道・往復 |
| 発生理由 | コード値 | 必須 | 表示名と分離 |
| 詳細 | 文字列500文字 | 条件付き | その他理由またはその他料金で必須 |

発生理由コードは次のとおりとする。

| コード | 表示 |
|---|---|
| `COMMUTING` | 通勤 |
| `RETURN_TO_OFFICE` | 帰社 |
| `OUTING` | 外出 |
| `CUSTOMER_SITE` | 常駐先 |
| `BUSINESS_PARTNER` | 取引先 |
| `HEALTH_CHECK` | 健康診断 |
| `TOKAICOM` | TOKAICOM（親会社） |
| `BUSINESS_TRIP` | 出張 |
| `OTHER` | その他 |

`TOKAICOM` は株式会社クエリの親会社を意味する。

## 6. 金額計算と異常値

各料金は片道料金として入力する。

```text
倍率 = 片道なら1、往復なら2
行合計 = (鉄道片道料金 + バス片道料金 + その他片道料金) × 倍率
月合計 = 全明細の行合計の合計
```

- クライアントとサーバーの両方で計算する。
- サーバーはクライアントから送信された行合計・月合計を信用せず再計算する。
- 金額は円単位の0以上の整数に限定する。
- 負数、小数、指数表記、通貨記号、数値以外を拒否する。
- 業務上の金額上限は設けない。
- 1明細の行合計が100,000円以上の場合は、保存・申請を拒否せず異常値警告と確認を表示する。
- Javaの安全な整数演算を使用し、数値型の上限超過や計算オーバーフローは400で拒否する。

## 7. 入力検証

- 対象年は2000年から2100年、対象月は1から12とする。
- 利用日は対象年月内の実在日だけを受け付ける。
- 発地、着地、利用区分、発生理由は必須とする。
- 鉄道、バス、その他のいずれかは1円以上とする。
- 発生理由が `OTHER` の場合は詳細必須とする。
- その他片道料金が1円以上の場合は詳細必須とする。
- 明細0件の申請は下書き保存できるが、申請できない。
- 101件目の明細追加・保存は拒否する。
- 同一明細は拒否せず警告だけを表示する。
- サーバー検証を正とし、入力不正は400と日本語メッセージを返す。

## 8. 状態管理

状態は次のとおりとする。

| 状態 | 意味 | 申請者編集 |
|---|---|---|
| `DRAFT` | 下書き | 可 |
| `PENDING_FIRST_APPROVAL` | 第1承認待ち | 不可 |
| `PENDING_SECOND_APPROVAL` | 第2承認待ち | 不可 |
| `PENDING_ACCOUNTING` | 総務精算待ち | 不可 |
| `RETURNED` | 差戻し | 可 |
| `SETTLED` | 精算済み | 不可 |

状態遷移は次の順序に限定する。

```text
DRAFT または RETURNED
  -> PENDING_FIRST_APPROVAL
  -> PENDING_SECOND_APPROVAL
  -> PENDING_ACCOUNTING
  -> SETTLED
```

- 第1・第2承認段階から `RETURNED` へ差戻しできる。
- 総務精算担当も精算前の不備を `RETURNED` へ差戻しできる。
- 差戻し理由は1文字以上500文字以下で必須とする。
- 差戻し後の再申請は第1承認からやり直す。
- 過去の承認履歴は削除しない。
- 状態遷移の順番を飛ばす操作は409で拒否する。
- `version` を用いた楽観ロックを実施し、競合時は409で再読み込みを促す。

申請日は `DRAFT` または `RETURNED` から申請操作を実行したサーバー当日の日付・時刻とする。下書き作成日は申請日として扱わない。

## 9. 承認者

申請者は申請時に第1・第2承認者を社員一覧から選択する。サーバーは選択時と承認実行時の両方で資格を検証する。

### 9.1 第1承認者

次の役職を選択可能とする。

- チーフ
- サブマネージャ
- マネージャー
- 部長
- 副社長
- 社長

### 9.2 第2承認者

次の部長クラスを選択可能とする。

- 部長
- 副社長
- 社長

### 9.3 共通制約

- 申請者本人を承認者に指定できない。
- 第1・第2承認者を同一人物にできない。
- 無効化された利用者を指定できない。
- 担当承認者本人だけが自分の段階を承認・差戻しできる。
- 承認時に役職要件を満たさなくなっている場合は承認を拒否し、申請者へ承認者変更を促す。
- 承認者変更は `DRAFT` または `RETURNED` だけで行える。

## 10. 総務精算担当権限

既存の一般、役職者、管理者とは別軸で、Spring Security authority `ROLE_EXPENSE_ACCOUNTING` を追加する。

- 管理者であるだけでは精算済み処理を実行できない。
- 一般、役職者、管理者のいずれにも追加付与できる。
- 利用者管理画面へ「総務精算担当」チェックを追加する。
- `ROLE_EXPENSE_ACCOUNTING` 保有者だけが総務精算待ち一覧、精算済み、総務差戻しを実行できる。
- 申請者本人は、自分の申請を精算済みにできない。

## 11. 電子印と本人性

申請者印、第1承認者印、第2承認者印、総務確認印を表示する。

- 申請、承認、精算済みの操作時に現在のログインパスワードで再認証する。
- パスワードはDB、承認履歴、監査ログ、アプリケーションログへ保存・出力しない。
- 社員表示名の姓を基に赤い丸印を画面・印刷時に生成する。
- 氏名に空白がある場合は先頭要素を姓として使用する。
- 氏名に空白がない場合は表示名の先頭2文字以内を使用する。
- 印影画像ファイルはアップロード、DB保存、ファイル保存しない。
- 電子印表示だけを本人性の根拠とせず、再認証、セッション、操作者、日時、内容ハッシュを証跡とする。

承認イベントへ次を保存する。

- 申請ID
- 操作者ユーザー名
- 操作者表示名
- 操作時の役職
- 押印役割
- 操作種別
- 操作日時
- 対象申請バージョン
- 内容SHA-256
- 差戻し理由

内容SHA-256は、対象年月、申請者、第1・第2承認者、順序付き明細、各料金、利用区分、発生理由、詳細、月合計を安定した形式へ正規化して計算する。

## 13. API

APIは `/api/transport-expenses` 配下へ分離する。

### 13.1 本人操作

- `GET /api/transport-expenses`: 自分の申請一覧
- `POST /api/transport-expenses/{year}/{month}`: 月次下書き作成
- `GET /api/transport-expenses/{id}`: 関係者向け詳細取得
- `PUT /api/transport-expenses/{id}`: 下書き・差戻し更新
- `POST /api/transport-expenses/{id}/submit`: 再認証して申請
- `GET /api/transport-expenses/approver-candidates`: 承認候補

### 13.2 承認者操作

- `GET /api/transport-expenses/approvals/pending`: 自分の承認待ち一覧
- `POST /api/transport-expenses/{id}/approve`: 担当段階を再認証して承認
- `POST /api/transport-expenses/{id}/return`: 理由付き差戻し

### 13.3 総務操作

- `GET /api/transport-expenses/accounting/pending`: 総務精算待ち一覧
- `POST /api/transport-expenses/{id}/settle`: 再認証して精算済み
- `POST /api/transport-expenses/{id}/accounting-return`: 理由付き差戻し

### 13.4 出力

- `GET /api/transport-expenses/{id}/export.xlsx`: 交通費帳票Excel

Excel出力は参照帳票のA4縦1ページを基準とし、対象年月、現在状態、現在有効な電子印を含める。100件の場合は1ページへ縮小せず、明細を複数ページへ分割して見読性を維持する。

## 14. Backend構成

交通費専用パッケージ `jp.co.query.attendance.transportationexpense` を作成する。

- Controller: HTTP入出力、Bean Validation
- Service: 認可、状態遷移、トランザクション、監査
- Repository: 交通費3テーブルのSQL
- Domain records/enums: 申請、明細、状態、利用区分、理由
- Calculator/Validator: 金額計算、入力検証、警告
- ContentHasher: 正規化とSHA-256
- ExportService: Excel帳票生成

勤務表のController、Service、Repository、計算クラスへ交通費処理を追加しない。

## 15. Frontend構成

- `TransportExpensePage.tsx`: 交通費画面の状態とAPI連携
- `TransportExpenseForm.tsx`: 申請・明細入力
- `TransportExpenseApproval.tsx`: 承認、差戻し、精算
- `transportExpense.ts`: 金額計算、入力検証、警告
- `transportExpense.css`: 交通費専用スタイル

`App.tsx` の変更は次に限定する。

- 交通費画面コンポーネントのimport
- `Screen` への交通費画面追加
- ホームの「交通費を入力」ボタン
- 戻る、ナビゲーション、印刷表示の接続

勤務表型、勤務表状態、勤務表API、勤務表入力コンポーネントへ交通費の型・状態・分岐を混在させない。

## 16. エラー処理

- 400: 入力不正、パスワード不一致、対象年月外日付、100件超過
- 403: 関係者以外の参照、担当外承認、権限不足、自己承認・自己精算
- 404: 申請または社員が存在しない
- 409: 状態遷移不正、対象年月重複、楽観ロック競合

本番応答へSQL、内部パス、スタックトレースを含めない。監査ログへパスワード、セッションID、CSRFトークンを記録しない。
