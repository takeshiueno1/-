# 勤怠管理システム 要件定義書

## 1. 文書の位置づけ

本書は、Excel勤務表の分析結果と、その後に追加・変更された要望を統合した現行要件である。実装状況は `04-implementation-status.md`、技術設計は `05-system-design.md`、Excelとの照合基準は `03-excel-fidelity-acceptance.md` を参照する。

要件の状態は次のとおり扱う。

- **確定**: 現行版で満たす要件
- **導入時**: 社内サーバー、ネットワーク、ID基盤の確定後に実施する要件
- **将来**: 現行版の対象外だが、拡張候補として保持する要件

## 2. 目的と基本方針

| ID | 状態 | 要件 |
|---|---|---|
| BR-001 | 確定 | Excelで行っている月次勤務表の入力、計算、案件別集計、帳票表示をWebシステムへ移行する。 |
| BR-002 | 確定 | 勤務表部分は提供済みの正社員・8時間勤務Excelを忠実に再現し、利用者の操作変化を抑える。 |
| BR-003 | 確定 | 社内利用を前提とし、約50人が利用できる。 |
| BR-004 | 確定 | 新たな有償クラウドや商用ライセンスを必須とせず、無償利用可能なソフトウェアで構成する。 |
| BR-005 | 確定 | 個人情報を扱うため、認証、認可、入力検証、監査、秘密情報保護を行う。 |
| BR-006 | 導入時 | 既存の社内サーバーへ配置し、外出先からはVPN等の安全な経路で利用する。インターネットへ直接公開しない。 |
| BR-007 | 導入時 | VPN内を含めTLSを使用し、バックアップと復元確認を運用する。 |

## 3. 利用者と権限

### 3.1 権限区分

| ID | 状態 | 要件 |
|---|---|---|
| ROLE-001 | 確定 | 一般利用者は本人の社員情報と勤務表だけを参照・更新できる。 |
| ROLE-002 | 確定 | 管理者は一般利用者の機能に加え、利用者管理、社員検索、他社員の勤務表参照・更新・削除、Excel取込、会社カレンダー取込、ログイン情報再発行を行える。 |
| ROLE-003 | 確定 | 管理者の代理操作は操作者と対象社員を区別して監査記録する。 |
| ROLE-004 | 確定 | Excel勤務表取込と会社カレンダーPDF取込は管理者だけが利用でき、画面だけでなくAPIでも権限を検証する。 |

### 3.2 利用者管理

| ID | 状態 | 要件 |
|---|---|---|
| USER-001 | 確定 | 管理者は利用者のユーザーID、所属、氏名、役職、社員コード、標準勤務時間、休憩時間、標準システム番号を登録できる。 |
| USER-002 | 確定 | 管理者は利用者の有効・無効を変更し、安全な仮パスワードを再発行できる。 |
| USER-003 | 確定 | 一般利用者の所属、氏名、役職、社員コードはログイン中の社員マスターから自動表示する。 |
| USER-004 | 確定 | ローカル検証時に限り、上野 豪の `test` ユーザーと約50人分の検証ユーザー・勤怠データを環境変数で作成できる。本番では無効にする。 |

## 4. 認証・セキュリティ要件

| ID | 状態 | 要件 |
|---|---|---|
| AUTH-001 | 確定 | システム内ユーザーIDとパスワードによるセッション認証を提供する。 |
| AUTH-002 | 確定 | ログイン時に未入力と形式を検証し、認証失敗時は文字化けしない日本語の文章を表示する。 |
| AUTH-003 | 確定 | パスワードはbcryptのコスト12でハッシュ化し、平文をDB、ログ、画面へ保存・表示しない。 |
| AUTH-004 | 確定 | 認証失敗が5回連続した場合は15分間ロックする。 |
| AUTH-005 | 確定 | 新規作成または管理者再設定後の仮パスワードは、初回ログイン時に本人用パスワードへ変更するまで業務画面を利用できない。 |
| AUTH-006 | 確定 | 本人用パスワードの有効期限は変更日から1か月とし、期限10日前からログイン時に期限日と残日数を通知する。期限後は変更するまで業務画面へ進めない。 |
| AUTH-007 | 確定 | パスワードを本人へ通知せず自動変更する方式は採用しない。自動ローテーション要望は、有効期限と本人による変更要求で実現する。 |
| AUTH-008 | 確定 | 30分間クリック、キー入力、タッチ、スクロールがない場合は再ログインを要求する。サーバーセッションも30分で失効する。 |
| AUTH-009 | 確定 | 同一ユーザーの同時セッションは1つに制限し、ログイン成功時はセッションIDを更新する。 |
| AUTH-010 | 確定 | 「ユーザーID・パスワードをお忘れの方はこちら」から、社員コードと氏名で管理者へ再発行依頼を登録できる。未認証画面ではアカウントの有無やユーザーIDを開示しない。 |
| AUTH-011 | 確定 | 社員コードが不明な場合は「Slackにて総務にお問い合わせください。」と案内する。 |
| AUTH-012 | 確定 | CSRF、XSS、SQLインジェクション、クリックジャッキング、不要なブラウザー権限、総当たり攻撃への対策を行う。 |
| AUTH-013 | 確定 | CookieはHttpOnly、SameSite=Strictとし、本番ではSecure属性を有効にする。 |
| AUTH-014 | 導入時 | 社内ID基盤が確認できた場合は、パスキーまたは社内SSOを検討する。端末指紋だけで本人識別しない。 |
| AUTH-015 | 導入時 | 外出先アクセスでは、VPNまたは将来導入する社内ID基盤の少なくとも一方で多要素認証を使用する。 |

## 5. 画面・UI要件

| UI-003 | 確定 | 会社ロゴを左上に表示し、黒背景になじむ大きさとする。黄色い正方形の「勤」アイコンは使用しない。 |

| UI-005 | 確定 | 一般以外の権限で操作中は、権限差を認識できるロイヤルブルー系グラデーションを使用する。 |
| UI-006 | 確定 | ホーム、管理者メニュー、パスワード変更、ログアウト、勤務表表示時の印刷をメインコンテンツ左側へ縦に配置する。管理者メニューだけ黄色、その他は白色を基調とする。 |
| UI-007 | 確定 | スマートフォン幅に対応する。勤務表のExcel列構成は維持しつつ操作可能な横スクロールまたは日次表示を提供し、それ以外の画面は1列表示へ適応する。 |

## 6. 勤務表機能

### 6.1 月次作成とカレンダー

| ID | 状態 | 要件 |
|---|---|---|
| TS-001 | 確定 | 西暦の対象年月から1日から月末までの日付と曜日を生成する。 |
| TS-002 | 確定 | 平日は社員マスターの標準始業、標準終業、休憩 `1:00`、標準システム番号を初期設定し、差異がある日だけ修正できる。 |
| TS-003 | 確定 | 土曜は指定休日、日曜は普通休日、祝日と会社休日は休日名を設定し、既定でグレーアウトする。 |
| TS-004 | 確定 | 会社固有休日は管理者が会社カレンダーPDFを取り込み、以降に新規作成または確認付き再初期化する勤務表へ反映する。 |
| TS-005 | 確定 | Pマーク運用確認日は翌月最初の営業日とし、上部罫線を含め見切れず表示する。 |
| TS-006 | 確定 | WG参加可否は「参加」「不参加」「当月未開催」から選択する。欄のどこをクリックしてもプルダウンが開き、文字は黒で表示する。 |
| TS-007 | 確定 | WGが「参加」で、業務内容にWGを示す記載がない場合は「WGの開催日時を業務欄に記載してください」と通知する。 |
| TS-008 | 確定 | 既存入力を消す再初期化は確認なしに実行しない。 |

### 6.2 日次入力

| ID | 状態 | 要件 |
|---|---|---|
| TS-IN-001 | 確定 | 始業、終業、休憩、休暇種別、業務内容、システムNo.を実績入力する。リアルタイム打刻は行わない。 |
| TS-IN-002 | 確定 | `1800` のような4桁入力を `18:00` へ変換する。休憩は `1:00` 形式で表示・入力する。 |
| TS-IN-003 | 確定 | 休日でグレーアウトした行を除き、始業、終業、休憩、休暇種別、業務内容、システムNo.を必須とする。ハイフンは入力済みとして扱う。 |
| TS-IN-004 | 確定 | 所属、氏名、役職、コード、Pマーク、WGも必須とする。未入力箇所は入力欄内へエラーを表示し、薄いピンク色にする。 |
| TS-IN-005 | 確定 | 複数日の変更は「変更をまとめて保存」で保存し、各項目・各行へ個別保存ボタンを配置しない。 |

### 6.3 計算・集計

| ID | 状態 | 要件 |
|---|---|---|
| CALC-001 | 確定 | 始業分と休憩分は15分単位で切り上げ、終業分は15分単位で切り捨てる。 |
| CALC-002 | 確定 | 労働時間を終業－始業－休憩で算出し、終業が始業より前の場合は日跨ぎとして24時間を加算する。 |
| CALC-003 | 確定 | 日曜勤務は休日労働時間へ計上する。 |
| CALC-004 | 確定 | 10:00より後の始業と16:00より前の終業を警告する。 |
| CALC-005 | 確定 | AM半休、PM半休、有給休暇、特別休暇、慶弔休暇、振替休日、欠勤を選択でき、Excelと同じ時間・日数換算を行う。 |
| CALC-006 | 確定 | 平日時間、休日時間、半休回数、所定日数、所定時間、過不足時間を集計する。 |
| CALC-007 | 確定 | システム番号別の日数・時間を集計し、5件を超えても欠落させない。 |

### 6.4 案件入力

| ID | 状態 | 要件 |
|---|---|---|
| PROJECT-001 | 確定 | 現行画面はExcelと同様に1日1案件を基本とする。案件別入力が必要な社員は日次のシステムNo.を手動修正する。 |
| PROJECT-002 | 将来 | 1日に複数案件へ時間配賦する画面を追加できるデータ構造を検討する。 |

## 7. 過去勤怠・削除・帳票

| ID | 状態 | 要件 |
|---|---|---|
| HIST-001 | 確定 | 登録済み月を一覧・月プルダウンから選び、過去勤務表を参照・編集して一括保存できる。 |
| HIST-002 | 確定 | 勤務表削除時は確認欄へ `削除する` と入力し、操作中ユーザー本人の現在パスワードで再認証する。共通固定パスワードは使用しない。 |
| HIST-003 | 確定 | 削除は論理削除とし、通常画面と履歴一覧から除外するが、監査・復旧用情報はDBへ保持する。 |
| HIST-004 | 確定 | 管理者が他社員を削除する場合も対象社員ではなく操作中管理者本人のパスワードを確認する。 |
| REPORT-001 | 確定 | Excelの月間表、案件別集計、所定時間・過不足、取締役・上長または担当リーダー・総務部確認欄に対応する印刷表示を提供する。 |
| APPROVAL-001 | 確定 | Excelに承認順序と状態遷移がないため、現行版は帳票上の確認欄だけを再現する。電子承認、提出、差戻し、月次締めは実装しない。 |

| COM-003 | 導入時 | Microsoft 365、Slack、社内メール運用の契約・権限・送信先を本番導入前に確認する。 |

## 11. 対象外

- 給与・会計システム向け出力
- 電子承認、提出、差戻し、月次締め
- リアルタイム打刻
- 位置情報、GPS、端末監視
- 1日複数案件への時間配賦画面
- 正社員・8時間勤務以外の帳票
- 提供済み以外のExcelレイアウト自動判別
- 画像PDFのOCR
- 社内ID基盤未確定の段階でのSSO・パスワードレス認証

## 12. 導入前の確認事項

1. 社内サーバーのOS、CPU、メモリ、空き容量
2. 既存VPNまたは新規VPNの利用可否
3. 本番ホスト名、TLS証明書、Secure Cookie設定
4. 社内ID基盤と多要素認証の有無
5. スマートフォンの利用対象が会社支給端末か個人端末か
6. Microsoft 365、Slackの利用契約と連携先
7. 正社員・8時間勤務以外の帳票と運用ルール
8. バックアップ、復元試験、ログ保管期間、監査担当者
