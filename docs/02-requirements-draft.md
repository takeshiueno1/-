# 勤怠管理システム 要件ドラフト

## 1. 目的と基本方針

Excelで行っている月次勤務表の入力、計算、案件別集計、帳票表示をWebシステムへ移行する。初版は提供されたExcelの仕様を忠実に再現し、その合格後に入力省力化等の追加機能を実装する。

- 利用者は現在約50人を想定する。
- 既存の社内サーバーへ配置する。
- 社内利用を前提とし、外出先からは安全な接続経路を通して利用する。
- 有償クラウド、有償API、商用ライセンスを必要としない構成にする。
- 個人情報を扱うため、認証、認可、暗号化、監査、バックアップを必須とする。
- 給与・会計システム向け出力は初版の対象外とする。

## 2. 初版の機能範囲

### 利用者機能

- ログイン、ログアウト
- 所属、氏名、役職、社員コード、勤務表種別の表示
- 対象年月、標準始業・終業時刻、標準システム番号の設定
- 対象月の勤務表初期化
- 西暦の年月・曜日に基づく月間カレンダー生成
- 土日、祝日、会社休日の自動設定
- WG参加可否の入力
- Pマーク運用確認日の自動設定
- 始業、終業、休憩、休暇種別、業務内容、システム番号の実績入力
- Excelと同じ15分丸め、休暇換算、警告表示
- 平日時間、休日時間、半休、所定日数、所定時間、過不足時間の集計
- システム番号別の日数・時間集計
- Excel帳票に対応する月間表示・印刷表示

### 管理者機能

- 利用者アカウント、所属、役職、社員コードの管理
- 利用者ごとの標準勤務時間と標準システム番号の管理
- 祝日、会社休日の管理
- 会社カレンダーPDFから会社休日を取り込み、勤務表の既定値へ反映
- 強い編集権限を持つ管理者による他社員の勤務表参照・更新
- 管理者だけが使用できる氏名、社員コード、所属、ユーザー名による社員検索
- 過去の `.xlsx` / `.xlsm` 勤務表を指定社員へ取り込み、DBへ登録
- 休暇種別の管理
- システム番号の管理
- アカウントの無効化とパスワード再設定
- 操作履歴の確認

### 承認機能

Excelには取締役、上長または担当リーダー、総務部の確認欄があるが、承認順序や状態遷移を制御するマクロはない。初版では帳票上の確認欄だけを再現し、電子承認、提出、差戻し、月次締めは実装しない。

## 3. 案件入力

- 基本操作はExcelと同じく、1日1件のシステム番号を入力する。
- 将来、1日に複数案件へ時間配賦できるよう、データ構造は1日複数明細を保持可能にする。
- 初版の画面では1件を標準表示し、追加明細の入力機能はExcel再現後の追加機能とする。
- システム番号別集計はExcelの5件制限を設けず、登録された全件を集計できるようにする。

## 4. 実績入力と省力化

リアルタイム打刻ではなく、実績入力方式を採用する。初版でもExcelの「適用」と同様に、平日へ標準始業・終業時刻、休憩時間、標準システム番号を自動設定し、利用者は差異がある日だけ修正できるようにする。

Excel再現後の追加候補は次のとおり。

- 前日または選択日の内容をコピー
- 選択期間へ同じ勤務パターンを一括適用
- 最近使用した業務内容・システム番号の候補表示
- 個人別の勤務パターン登録
- 未入力日、通常と異なる勤務日のみを絞り込み表示

## 5. 雇用区分・勤務表種別

ここでいう雇用区分とは、勤務時間や休暇計算が異なる利用者の分類を指す。Excelマクロからは、少なくとも正社員の8時間勤務、6時間勤務、7時間勤務、協力会社、日給の分岐が確認できる。

初版は提供された正社員・8時間勤務の帳票を基準にする。所定労働時間は利用者ごとに設定できる構造とし、他の区分は該当するExcel帳票と運用ルールを確認してから追加する。

## 6. システム構成

- 形態: スマートフォン対応のレスポンシブWebアプリケーション
- フロントエンド: React + TypeScript
- バックエンド: Spring Boot
- データベース: PostgreSQL
- 配置先: 既存の社内サーバー
- 実行方式: Linux上のコンテナを第一候補とし、無償利用できるDocker EngineまたはPodmanを使う
- 外出先アクセス: WireGuard等のVPNを第一候補とする
- リバースプロキシ: CaddyまたはNginx

社内サーバーをインターネットへ直接公開しない。外出先からはVPNへ接続し、その後に社内向けURLへアクセスする。通信はVPN内でもTLSで暗号化する。

## 7. 認証とセキュリティ

社内ID基盤の有無が現時点で不明なため、初版はシステム内アカウントで動作可能にする。将来SSOが利用できると判明した場合に差し替えられる構成とする。

- パスワードは平文保存せず、Argon2idまたはbcrypt等の安全な方式でハッシュ化する。初版はbcryptのコスト12を使用する。
- 初回ログイン時のパスワード変更を必須にする。
- ログイン失敗回数制限、一定時間のロック、セッション有効期限を設ける。
- VPNまたはアプリケーションの少なくとも一方で多要素認証を使用する。
- 利用者は本人の勤怠だけを閲覧・更新できる。
- 管理者は対象社員を明示的に選択した場合に限り、他社員の勤怠を閲覧・更新できる。代理操作は監査ログへ記録する。
- 管理者権限を一般利用者から分離し、必要最小限に付与する。
- 通信をTLSで暗号化する。
- 操作履歴には操作者、日時、対象、変更内容を記録する。
- パスワード、セッショントークン、勤務内容をアプリケーションログへ出力しない。
- CSRF、XSS、SQLインジェクション、総当たり攻撃への対策を行う。
- データベースとバックアップへのアクセス権を限定し、バックアップを暗号化する。
- 日次バックアップと定期的な復元確認を行う。
- 有償の外部監視・分析サービスへ個人情報を送信しない。

会社カレンダーPDFは管理者だけがアップロードできる。PDF本体は保存せず、ファイル名、ハッシュ、取込者、抽出日数と抽出した休日を記録する。誤登録防止のため、日付と「休日」「休暇」等の休日名を文字として抽出できるPDFだけを対象とし、画像だけのPDFは受け付けない。

## 8. 費用の扱い

ソフトウェアと開発サービスは無償・オープンソースで構成し、新たな有償契約を前提にしない。ただし、既存サーバー、ネットワーク回線、電気、ドメイン、証明書の管理、バックアップ媒体、保守担当者の作業はゼロにはならないため、既存設備で賄えるかを導入前に確認する。

## 9. 過去Excel移行

- 管理者が取込先社員を明示してからExcelをアップロードする。
- 提供済みの「勤務表」シート配置を基準に、対象年月、日次時間、休憩、休暇、業務内容、システム番号、WG参加可否を取り込む。
- パスワード付き `.xlsm` に対応する。
- Excel本体とパスワードは保存しない。
- ファイルハッシュ、取込者、取込先、対象年月、行数を記録する。
- 同月データは明示確認がない限り上書きしない。
- Excel記載の氏名・コードと取込先が異なる場合は警告する。

## 10. 現時点の対象外

- 給与・会計システム向け出力
- 電子承認、提出、差戻し、月次締め
- リアルタイム打刻
- 位置情報、GPS、端末監視
- 有償クラウド、有償APIへの依存
- 異なる勤務表レイアウトを自動判別する汎用移行

## 11. 残る確認事項

1. 社内サーバーのOS、CPU、メモリ、空き容量
2. 社内ネットワークにVPNを追加できるか、既存VPNがあるか
3. 社内ID基盤の有無を確認できる担当部署または担当者
4. 正社員・8時間勤務以外のExcel帳票が存在するか
5. スマートフォンは会社支給端末だけか、個人端末も許可するか
6. Pマーク確認、WG参加可否、健康診断処理を全利用者に適用するか
7. 提供済みレイアウト以外の過去Excelが存在するか
