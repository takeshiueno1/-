## 2. 目的

従来のExcel勤務表の入力項目、計算、表示、案件別集計を維持しながら、社員情報と勤怠情報をPostgreSQLで一元管理する。社内サーバーへ配置し、社外からはVPN等の安全な経路を通じて利用する。

## 3. 対象範囲

- ユーザー認証、パスワード変更、再発行依頼
- 社員マスター管理と管理者による社員検索
- 月次勤務表の作成、入力、計算、保存、履歴参照、論理削除
- 管理者による他社員の勤務表参照・更新
- 会社カレンダーPDF取込
- 過去Excel勤務表取込
- Excel勤務表出力、PC版Outlookの下書き作成、Slack連絡
- 監査ログ、セキュリティ、バックアップ・復旧運用

電子承認、提出・差戻し、月次締め、給与・会計システム向け出力は現段階では対象外とする。

## 4. 利用者と権限

| 区分 | 主な権限 |
|---|---|
| 一般利用者 | 自分の社員情報・勤務表の作成、参照、更新、削除、Excel出力、連絡 |
| 役職者 | 一般利用者の権限、全社員検索、他社員勤務表の代理参照・更新 |
| 管理者 | 役職者の権限、他社員勤務表の削除、利用者管理、Excel取込、会社カレンダー取込 |

役職者向けAPIは`ROLE_MANAGER`または`ROLE_ADMIN`、管理者APIは`ROLE_ADMIN`をサーバー側で検証する。

## 5. 機能要件

### 5.1 認証

- ユーザーIDとパスワードを必須とし、不正時はアカウントの存在を推測できない共通エラーを表示する。
- パスワードは12～128文字とし、推測されやすい値とユーザーIDを含む値を拒否する。
- パスワードはBCrypt cost 12で保存し、平文をDB、ログ、Gitへ保存しない。
- 5回連続失敗時は15分間ロックし、認証成功時に失敗回数をリセットする。
- 仮パスワード利用者は初回変更を必須とする。
- 本人変更後は1か月を有効期限とし、10日前から警告する。無通知の自動変更は行わない。
- 30分間無操作の場合は再ログインを要求し、同一ユーザーの同時セッションは1件とする。
- 再発行依頼は社員コードと氏名を用い、未認証画面でユーザーIDを返さない。

### 5.2 ホーム・ナビゲーション

- ログイン後に「新規で勤務表を作成」「過去分を参照・編集」を選択できる。
- 左側へホーム、管理者メニュー、パスワード変更、ログアウト、連絡を縦配置する。
- 右上には現在の利用者の氏名と所属部署だけを表示する。
- 一般画面は黒のグラデーション、管理者画面はロイヤルブルーのグラデーションを基本とする。

### 5.3 勤務表

- Excel勤務表の列構成、罫線、見出し、Pマーク運用確認日、WG欄を忠実に再現する。
- 西暦カレンダーから対象月の日付と曜日を生成し、土日・祝日・会社休日を休日表示する。
- 所属、氏名、役職、社員コードはログイン中の社員マスターから自動設定する。
- 平日は始業、終業、休憩、休暇種別、業務内容、システムNo.を必須とし、ハイフンを入力済みとして扱う。
- 未入力欄は薄いピンク色にし、欄内へ日本語エラーを表示する。
- `1800`を`18:00`へ変換し、始業は15分単位切上げ、終業は15分単位切捨て、休憩は15分単位切上げとする。
- 休憩は`1:00`形式で表示する。
- WGが「参加」で業務内容にWGを示す記載がない場合、開催日時の記載を促す。
- 日次変更は画面下部の「変更をまとめて保存」で一括保存する。
- 基本は1案件、必要な利用者だけ複数のシステムNo.・案件時間を入力できる。

### 5.4 過去勤怠・管理者機能

- 年月を選択して登録済み勤務表を参照・編集できる。
- 役職者と管理者だけが氏名、社員コード、所属、ユーザーIDで社員を予測検索できる。
- 候補選択後は候補一覧を閉じる。
- 削除時は確認文字`削除する`と操作中ユーザー本人のパスワードを必須とする。
- 削除は論理削除とし、操作者、対象、日時を監査ログへ記録する。

### 5.5 ファイル・外部連携

- Excel取込と会社カレンダーPDF取込は管理者だけが実行できる。
- 取込ファイルは10MB以下とし、拡張子、署名、ページ数、入力値を検証する。
- Excelパスワードとファイル本体は保存せず、ファイル名、SHA-256、取込件数、操作者を保存する。
- Outlookは本人の保存済み勤務表をExcel添付した未送信メールとしてPC版Outlookで開く。
- Outlook用URLは256ビット乱数、有効期限2分、一度限りとし、アクセスログへ残さない。
- Slack Webhookが設定済みなら指定チャンネルへ投稿し、未設定時はSlack画面を開く。
- 管理者が他社員を代理表示中は誤送信防止のため連絡機能を表示しない。

## 6. 非機能要件

| 分類 | 要件 |
|---|---|
| セキュリティ | VPN、TLS、MFA、CSRF/XSS/SQLインジェクション対策、最小権限、秘密情報分離 |
| 可用性 | コンテナ自動再起動、DBヘルスチェック、日次バックアップ |
| 性能 | 約50名、通常月の勤務表表示・保存を業務上支障のない時間で処理 |
| 保守性 | FlywayによるDB移行、Gitによる版管理、リリースノート作成 |
| 監査 | 管理者代理操作、削除、取込、外部連携を記録 |
| 対応端末 | 最新Edge/Chrome、Windows 10/11、スマートフォン |

## 7. 本番移行条件

- VPNまたは社内ネットワーク内に限定し、インターネットへ直接公開しない。
- 正式ホスト名とTLS証明書を設定し、`SESSION_COOKIE_SECURE=true`とする。
- 外出先経路または社内ID基盤でMFAを有効にする。
- 本番用ランダムパスワードを設定し、テストデータ投入を無効化する。
- バックアップだけでなく、別環境への復元試験を完了する。
- 受入テストの高優先度ケースがすべてOKで、重大・高の未解決不具合が0件である。
