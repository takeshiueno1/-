# 勤怠管理システム 運用手順書

## 1. 運用体制

| 役割 | 責務 |
|---|---|
| システム管理者 | サーバー、TLS、VPN、バックアップ、監視、リリース |
| 勤怠管理者 | 利用者管理、再発行、会社休日・過去Excel取込 |
| 一般利用者 | 本人勤務表の入力、確認、Excel出力、連絡 |
| 情報セキュリティ担当 | 権限棚卸し、ログ点検、脆弱性対応、インシデント対応 |

## 2. 日常運用

### 毎日

1. `docker compose ps`でDBとBackendがhealthy、Frontendがrunningであることを確認する。
2. エラーログの急増、連続ログイン失敗、取込失敗を確認する。
3. DBバックアップの終了状態とバックアップサイズを確認する。
4. 問題がある場合は時刻、利用者、操作、画面、エラー文を記録する。パスワードや個人情報を証跡へ貼り付けない。

### 毎月

1. 翌月の会社休日を管理者画面で確認し、必要なら会社カレンダーPDFを取り込む。
2. 退職・異動・管理者権限を棚卸しする。
3. OS、Docker、コンテナイメージ、Java・npm依存関係の更新有無を確認する。
4. 復元試験用環境へ最新バックアップを復元し、ログインと勤務表参照を確認する。
5. 監査ログとバックアップの保存期間超過分を社内規程に従って削除する。

### 四半期

1. 管理者権限を責任者が再承認する。
2. VPN・MFA・TLS設定を点検する。
3. 脆弱性診断、復旧訓練、インシデント連絡網の確認を行う。

## 3. 利用者管理

- 利用開始時は管理者が社員情報を確認し、安全な仮パスワードを発行する。
- 仮パスワードは本人確認後に別経路で通知し、初回ログインで変更させる。
- 異動時は所属・役職を更新し、退職時は最終利用日までにアカウントを無効化する。
- 管理者権限は必要最小人数とし、一般業務用アカウントと分離することを推奨する。
- 再発行依頼は総務が本人確認した後に処理する。

## 4. バックアップ

日次バックアップの例：

```powershell
$stamp = Get-Date -Format 'yyyyMMdd-HHmmss'
docker compose exec -T db pg_dump -U attendance -d attendance -Fc |
  Set-Content -AsByteStream "D:\attendance-backup\attendance-$stamp.dump"
```

- バックアップ先はアクセス制限し、可能なら暗号化する。
- 同一サーバーだけでなく、社内規程に沿った別媒体・別筐体へ複製する。
- バックアップ取得だけを成功条件にせず、月1回以上復元を確認する。
- DBボリュームを削除する`docker compose down -v`は通常運用で使用しない。

復元は本番へ直接行わず、最初に隔離した検証環境で確認する。本番復元は責任者承認と停止時間の周知後に実施する。

## 5. 監視と障害対応

| 事象 | 初動 |
|---|---|
| 画面を開けない | Frontend、Backend、DBの順に状態・ログを確認 |
| ログインできない | ロック、有効状態、期限、社員情報を確認。パスワードを閲覧しない |
| DB障害 | 書込みを停止し、ディスク・ログ・バックアップを確認 |
| 誤削除 | 論理削除データと監査ログを確認し、復旧手順を別途承認 |
| 情報漏えい疑い | 外部接続を遮断し、ログと証跡を保全してセキュリティ担当へ連絡 |

障害時にログやDBをメール・Slackへそのまま添付しない。個人情報をマスキングし、社内の承認済み経路で共有する。

## 6. セキュリティ運用

- システムをインターネットへ直接公開しない。
- VPNまたは社内ID基盤でMFAを必須とする。
- TLS証明書の期限を監視する。
- `.env`、秘密鍵、バックアップ、ログをGitHubへ登録しない。
- 本番では`APP_DEMO_SEED_ENABLED=false`、`APP_TEST_USER_ENABLED=false`を維持する。
- `SESSION_COOKIE_SECURE=true`を設定する。
- Outlook・Slackの資格情報は年1回以上、または漏えい疑い時に直ちに更新する。

## 7. データ保持

保存期間は就業規則、法務・個人情報保護方針に従い、勤怠、監査ログ、取込履歴、バックアップごとに社内責任者が決定する。現段階ではアプリが自動削除しないため、本番開始前に保存期間と削除承認手続きを確定する。
