# スマートフォン利用・テスト仕様

## 1. 対象

- 最新版のiOS Safari、Android Chrome
- 画面幅320px～520px
- PCとスマートフォンが同じ信頼できる社内LANまたは家庭内LANに接続されていること
- Dockerなしデモの標準ポートは `4280`。デスクトップ上の検証版v3は `4282`

## 2. 起動・接続

1. PC側で通常版が動作している場合は終了する。
2. Dockerなしデモに同梱する `スマホで確認.cmd` を実行する。
3. 黒い画面へ表示された `http://PCのIPv4アドレス:ポート/` をスマートフォンで開く。
4. Windowsファイアウォールの確認が表示された場合は、プライベートネットワークだけを許可する。

通常の `デモを起動.cmd` は `127.0.0.1` だけで待ち受けるため、スマートフォンからは接続できない。スマホ確認起動では `SERVER_ADDRESS=0.0.0.0` を設定し、同一LANからの接続を許可する。

## 3. スマートフォンUI仕様

| 項目 | 仕様 |
|---|---|
| ナビゲーション | 幅520px以下で画面下部へ固定し、アイコンと短いラベルを表示する |
| タップ領域 | 主要なボタン、入力欄、選択欄を44px以上とする |
| ヘッダー | 画面上部へ固定し、ロゴ、戻る、ログイン中の利用者を表示する |
| 勤務表 | 日付単位のカードへ変換し、横スクロールなしで日次入力できる |
| 保存 | 勤務表上部へ保存ボタンを固定し、長い月でも操作できる |
| 連携 | Outlook・Slack操作を本文側へ表示し、下部ナビゲーションと重ならない |
| 管理画面 | 入力フォームとカードを1列表示にする |
| PC・印刷 | PCではExcel型の表、印刷では従来のA4勤務表を維持する |

## 4. セキュリティ制約

- スマホ確認起動は説明・検証専用であり、公衆Wi-Fiやインターネットへ公開しない。
- 個人所有端末へ本番の個人情報や勤務表ファイルを保存しない。
- 本番の外出先アクセスは、HTTPS、VPNまたは社内ID基盤、MFA、端末管理を前提とする。
- Windowsファイアウォールへ恒久的な受信規則を自動追加しない。必要な場合もプライベートネットワークだけを対象とする。

## 5. 受入テスト

| ID | 確認内容 | 期待結果 |
|---|---|---|
| SP-01 | 390×844でログイン画面を表示 | 横方向にはみ出さず、入力とログインボタンを操作できる |
| SP-02 | 一般・管理者ホームを表示 | 下部ナビゲーションが表示され、本文を隠さない |
| SP-03 | パスワード変更を表示 | 3つの入力欄が伏字で、目アイコンから個別に表示切替できる |
| SP-04 | 勤務表を表示 | 日次行がカードになり、横スクロールなしで入力できる |
| SP-05 | 始業へ `1800` を入力 | `18:00` に変換される |
| SP-06 | 必須項目を空にして保存 | 対象欄が薄いピンクになり、入力欄内へ必須エラーを表示する |
| SP-07 | 保存ボタンを操作 | 画面上部の固定ボタンから月次変更を一括保存できる |
| SP-08 | 管理者メニュー・社員検索 | 1列表示で候補選択後に候補一覧が閉じる |
| SP-09 | LANアドレスのヘルスチェック | `http://PCのIPv4アドレス:ポート/actuator/health` が `UP` を返す |
| SP-10 | PC幅と印刷表示 | Excel型の表とA4印刷レイアウトに回帰がない |

自動テスト、縮小ビューポートの実画面確認、LANアドレスからのHTTP確認を実施する。実機固有のSafari・Chrome差異とWindowsファイアウォールの許可操作は、会社で使用する端末による最終受入テスト対象とする。

| SP-02 | OK | 下部ナビゲーションが固定表示され、本文へ74pxの下余白が確保されることを確認 |
| SP-03 | OK | パスワード入力の初期型が `password`、目アイコン押下後が `text` になることを確認 |

| SP-06 | OK | 必須の業務内容が `aria-invalid=true`、背景 `rgb(255, 240, 243)`、プレースホルダー「必須入力」になることを確認 |

あわせてFrontendのLint・TypeScript・Viteビルドと、Backendの自動テスト41件を実行してすべて成功した。実機のiOS Safari、Android Chrome、会社PCのWindowsファイアウォール許可操作は、利用端末を使う最終受入テストに残る。
